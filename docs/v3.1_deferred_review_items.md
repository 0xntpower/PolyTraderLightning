## TIER 1 — High-risk fragility (not yet addressed)

### F1. MomentumSignalStrategy has ~30 mutable fields and 5 interacting post-fire code paths

**File:** `src/strategy/momentum_signal.py`

This is the single highest bug-density area in the codebase and owns the v3.0
losses. Fields span: Welford accumulators, entry flags, maker/taker IDs, CUSUM
state, EMA state, sustain/reversal/override timers, fire metadata, Kelly cache,
warmup flags, variance subsample state. The `_monitor_post_fire_erosion` method
has five interacting gates (panic / sustain / reversal / top-bid / v3.1
override), and `reset()` has to remember to clear them all.

**Partial mitigation already in place:** `TestResetInvariant` (Item 6, committed
`015cb39`) catches any future `reset()` drift on the current field set.

**Remaining refactor — staged, safe order:**
1. Extract a frozen `PostFireContext` dataclass holding `fire_delta_pct`,
   `fire_time`, `fire_mid`, `entry_price`, `entry_size_usd`, `side`. Set it once
   in `_finalize_entry`; reject mutation. This collapses the three
   `_finalize_entry` call sites (maker fill, taker escalation, direct taker)
   from ~10 hand-set fields each to one assignment.
2. Extract a `CusumMonitor` class owning `_erosion_ema`, `_erosion_cusum`,
   `_cusum_breach_started_at`, `_panic_breach_started_at`. Accepts
   `(raw_erosion, current_pct, fire_delta_pct, top_bid, now)` and returns an
   enum `{HOLD, EXIT_CUSUM, EXIT_PANIC, OVERRIDE_EXIT}`. This is the single
   most testable unit in the bot — mock the clock, feed synthetic ticks.
3. After the extraction, port the existing `test_momentum_signal.py` CUSUM
   tests onto the new `CusumMonitor` class so regressions surface in the unit
   rather than through the full strategy fixture.

**Why deferred:** refactoring the post-fire erosion state machine right before
a profit-or-abandon paper session is how you ship a subtle semantic change
disguised as a cleanup. Do it post-v3.1 with v3.1 logs as a regression
baseline — diff CUSUM decisions on the real window-by-window tape before and
after.

**Effort:** ~3h for the `CusumMonitor` extraction alone. Add ~2h if the
`PostFireContext` dataclass lands in the same pass.

### F2. SignalLifecycle reaches into strategy private attributes

**File:** `src/strategy/signal_lifecycle.py` (lines ~213, ~239)

`SignalLifecycle` currently reads/writes `sh.signal._fired` and calls
`_conditions_met()` directly. A lifecycle class that directly mutates `_fired`
on the strategy creates a hidden state-machine contract. The moment
`_conditions_met` grows a side effect (it already reads `_latest_pct` and is
close to one), this breaks.

**Fix:** add a public `shadow_tick(signal, time_remaining) -> bool` method on
`MomentumSignalStrategy` that accumulates and returns whether conditions fired,
without actually placing orders. Lifecycle calls that instead of poking
`_fired` directly.

**Effort:** ~2h + lifecycle tests.

### F3. MarketState is shared mutable state with no lock or ownership model

**File:** `src/market_data/state.py`

20+ mutable fields touched by: Binance WS consumer, Chainlink WS consumer, CLOB
book WS, user WS, strategy loop, window tracker, resolution manager. All
correct only because asyncio is single-threaded and there are no `await` points
between read and write in any given handler. Any future `await` inside a
mutation block (e.g. adding Discord alerts) will introduce races.

**Fix (cheap — do first):** document the contract on the class — "no method on
this class may `await`; all mutations must be synchronous" — and add a ruff
rule or a pytest regex check that greps for `await` inside
`market_data/state.py`. This locks in the invariant without restructuring
anything.

**Fix (proper — defer):** partition the state: one dataclass per producer
(`BinanceState`, `ChainlinkState`, `CLOBState`), frozen snapshots returned to
the strategy loop. The strategy reads a snapshot, not the live object.

**Effort:** cheap fix ~30min. Proper partition ~6h and touches a lot of files.

### F5. `_WILSON_Z = 1.5` and feedback constants hardcoded in Python

**File:** `src/strategy/kelly.py`

Comment says "Must match kWilsonZ in engine Config.hpp" — this is a
cross-language invariant with no enforcement. If the engine bumps to 1.96,
live/backtest will silently diverge and every trade-selection test will drift.

**Fix:** read `z` from `bot-config.yml` (default 1.5). Add a pytest that reads
both `bot-config.yml` and the engine's `Config.hpp` (simple regex) and asserts
they match. CI gate.

**Effort:** ~4h because of the cross-repo glue. Worth it: this is the kind of
silent divergence that is impossible to debug from bot logs alone.

### F6. `WindowTracker` prefetch uses two parallel slots with ad-hoc lifecycle

**File:** `src/strategy/window_tracker.py`

Two `asyncio.Task`s (current + prefetch) managed via assignments to
`self._current_fetch_task` / `self._prefetch_task`. No cancellation on
shutdown. No test for "prefetch is swapped into current when window rolls."

**Note:** the Item 3 fix (`_harvest_task_result`) addressed the
`except BaseException` hazard but did NOT reorganize the task lifecycle — the
two-slot pattern is still in place.

**Fix:** use `asyncio.TaskGroup` (3.11+) or a small `TokenFetcher` helper class
that owns both slots and guarantees cancellation in `close()`. Add a test that
asserts slot swap on `on_new_window()`.

**Effort:** ~3h including the swap test.

### F7. `paper_trading.WindowRecord` is unfrozen + wall-clock in maker-fill check

**File:** `src/execution/paper_trading.py`

Two separate issues in the same file:

1. `@dataclass` is not `frozen=True, slots=True` — HRP default violation.
   Mutation after construction is required (fields get filled in over the
   window lifetime), so if staying unfrozen is the right call, add a comment
   explaining why.
2. `_check_maker_fill` uses `time.time() - order.submitted_at` — wall-clock.
   An NTP step (or any clock adjustment) can flip a pending maker to instantly
   filled or eternally unfilled. Use `time.monotonic()` for the elapsed check
   and keep the wall-clock `submitted_at` only for logs.

**Effort:** ~1h. Low risk, high payoff for paper-trading determinism.

### F8. Resolution fallback "conservative loss" is asymmetric

**File:** `src/strategy/resolution.py`

`_force_resolve_outcome` writes a loss when no snapshot is available after
1200s. In the absence of ground truth, always-lose is an accounting bias: over
a session, if 2% of resolutions time out and they were actually 50/50, we
overstate losses by ~1% of volume. Aggregated across a paper run, this is
exactly the kind of quiet bias that makes a marginal strategy look
unprofitable.

**Fix options — pick one:**
1. Record as `UNRESOLVED`, exclude from P&L and Kelly feedback entirely.
2. Use the last observed mid from CLOB as the resolution proxy.

Also: 1200s is very long. If the Gamma API is unreachable we want to know
within 60–120s. Add an exponential backoff with shorter first attempts.

**Effort:** ~2h + a regression test that exercises the Gamma-unavailable path.

**Priority note:** if v3.1 shows marginal/slightly negative P&L and Gamma
timeouts in the JSONL, this fix alone might flip the sign.

## TIER 2 — Medium-severity correctness & HRP compliance

### M1. `except Exception` in `_strategy_loop`

**File:** `src/main.py:1159`

The comment justifies "don't crash the hot loop" but HRP forbids bare
`except Exception`. It hides real bugs; we've probably already absorbed some.
List the three real sources (`ConnectionError`, `asyncio.TimeoutError`,
`KeyError` from state lookups), and any other exception should kill the loop
and page the operator via Discord.

**Effort:** ~1h + a test that an unhandled exception now propagates.

---

### M2. `dict[str, Any]` at known schema boundaries

HRP requires `TypedDict` at known boundaries. Three concrete sites:

- `resolution._write_live_window_record` → returns `dict[str, Any]` to JSONL.
  Define `LiveWindowRecord` `TypedDict`.
- `window_handler._PendingSignalMgr.take_pending` → returns
  `tuple[dict[str, Any], str]`. Define `PendingSignal` `TypedDict`.
- `fakes.FakeStrategy._kelly_fields: dict | None`. Define `KellyFieldsDict`
  `TypedDict`.

**Effort:** ~2h. Zero behavioral risk, catches real bugs at type-check time.

### M3. `sys.exit(1)` in main on signal validation failure

**File:** `src/main.py` in `_wait_for_first_signal` / preflight.

Hard `sys.exit` is fine for standalone runs, but under orchestrator/watchdog
the bot needs to return a non-zero code AND flush logs first. Verify
`logging.shutdown()` runs via `atexit` or a top-level `finally`.

**Effort:** ~30min + manual verification against the orchestrator harness.

### M4. `_save_paper_balance` is not atomic

**File:** `src/strategy/window_handler.py`

Reads-then-writes `state.json` without a tempfile. A crash between read and
write truncates state. `BankrollTracker._save` already uses the right pattern
(`mkstemp` + `os.replace`).

**Fix:** refactor `_save_paper_balance` to use the same `mkstemp`/`os.replace`
sequence. Optionally factor out a shared `atomic_write_json(path, data)`
helper so there's one implementation.

**Effort:** ~1h including the helper.

## TIER 3 — Test effectiveness

### W1. Ban `MagicMock` in this codebase

**Files:** `tests/test_resolution.py` (~15 patches), `tests/test_open_price_fetch.py`.

`MagicMock` accepts any attribute access and returns another mock, so
production-code renames silently still pass tests. The Fake* class pattern
already in `test_window_handler.py` and `fakes.py` is the right model.

**Fix:** migrate `test_resolution.py` and `test_open_price_fetch.py` onto the
Fake* pattern. Add a ruff rule or a conftest import hook that blocks
`MagicMock` / `unittest.mock.patch` at the source level.

**Effort:** ~3h for the migration.

---

### W2. Fakes drift from production types

Concrete drift found during the review:

- `FakeJournal.record_trade` returns `bool`; real `TradeJournal.record_trade`
  returns `None`.
- `FakeOrderExecutor.mode = "test"` — doesn't match `"paper"` or `"live"`, so
  any code branching on mode silently takes the `else` branch.
- `FakeBankrollTracker.win_calls: list[tuple]` — untyped tuple.
- `test_resolution.py` has `type: ignore[arg-type]  # test fake uses str
  values`.

**Fix:** every Fake inherits from the production `Protocol`/`ABC`. Use
`runtime_checkable` Protocol in production code and
`assert isinstance(fake, Protocol)` in `conftest.py`.

**Effort:** ~2h.

---

### W5. No end-to-end live-mode integration test

All live-mode fills currently go through mocked `_live_fill`. At minimum add a
test that drives a fake CLOB user-WS message through the same path as the real
consumer and asserts the resolution pipeline finalizes correctly.

**Effort:** ~4h — requires building a `FakeCLOBWebSocket` fixture.

**Priority note:** this is the gap that let the paper-vs-live divergence bugs
hide last quarter. Do it before the first real-money session.

### W7. No test for the thread-pool starvation scenario (C4 / Item 8)

**File:** `tests/test_order_manager.py` (does not exist yet).

Hard to test directly, but an `inspect.getsource`-based static assertion works:

- `OrderManager.__init__` creates its own `ThreadPoolExecutor`.

shared default executor.
